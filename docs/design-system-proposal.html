Internal · Design system proposal

One system. One feel.
A polished minesweeper.

The app has the bones of a great UI — the palette is right, the radii are friendly, the layout is sound. What it lacks is a system: a single typography ramp, a single space scale, a single set of primitives that every screen reuses. This document proposes that system, derived from what you already have, with the inconsistencies cleaned up.

SCOPE · Lobby, Game, Account, Leaderboard, Auth FILES TOUCHED · ~24 SCSS modules NEW PRIMITIVES · 9 BREAKING TOKEN CHANGES · 0 (additive)
01

The audit

What's actually inconsistent today, by category. Five real findings traced back to specific files.

CRITICAL

No type scale

Every component picks its own font-size in rem. There's no canonical body, label, or title size, so 20+ near-duplicate sizes appear across the app.

Sizes in the wild: 0.64, 0.65, 0.7, 0.72, 0.75, 0.76, 0.78, 0.8, 0.82, 0.84, 0.86, 0.875, 0.9, 0.92, 0.94, 0.95, 0.98, 1, 1.1, 1.2, 1.25, 1.5, 1.9, 2+
CRITICAL

No spacing scale

Tokens exist (--space-1/2/3) but only cover 8/16/24px. Everything in between is hardcoded — 4px, 6px, 10px, 12px, 14px, 18px, 20px — in 40+ places.

e.g. LobbyCard: 12px, 10px, 8px, 5px, 4px, 6px, 7px · GameHeader: 4px, 6px, 8px, 12px
REPETITION

Same component, 4 implementations

Pattern duplicated across the app with slightly different paddings, radii, and shadows each time. These should be primitives.

Segmented control: SelectLevelToggleGroup · SelectDigFlag · ModeToggle · Leaderboard tabs
Badge / pill: DailyBadge · youBadge · LobbyCard.badge · GameStatus.statusPill
Stat tile: DailyCard.stat · ContinueBanner.stat · LevelCard.meta · BestScores.scoreRow
Dialog: LevelChangeDialog · ContinueBanner.dialog (same @keyframes dialogEnter defined twice)
REPETITION

Accent colors hardcoded as rgba

--accent-blue exists but rgba(77, 163, 255, 0.X) is written inline 30+ times. Same for rgba(255, 92, 122, 0.X) (danger). Tokens can't be swapped or themed.

rgba(77, 163, 255, …) in: Button, Switch, LobbyCard, ContinueBanner, LeaderboardPage, OnboardingTour, …
Fix: ship a token opacity ramp — --accent-14, --accent-24, --accent-48.
POLISH

Font-weight inflation

Weights 400 / 600 / 700 / 800 / 900 all appear, often without semantic intent — an "eyebrow" is 800 in LevelCard, 700 in LobbyCard, 900 in ContinueBanner. Standardize to regular / medium / semibold / bold.

900: LobbyCard.eyebrow, LevelCard.meta, ContinueBanner.statLabel, .statValue, .actionButton
800: LobbyCard.eyebrow (also!), DailyBadge, DailyCard.stat dd, ToggleGroup.label
Same role, two weights, different files.
POLISH

Eyebrow letter-spacing drift

Uppercase eyebrow labels exist on most surfaces, but every implementation picks a different letter-spacing — 0.04em, 0.06em, 0.08em, 0.1em, 0.12em. Tiny inconsistency, big "off" feeling.

Canon: every uppercase label uses letter-spacing: 0.08em, font-weight: 600, size: 11px.

2.1   Color

2.6   Motion

Three durations cover everything: press, hover/micro, enter/exit. Two easings: standard, out.

--dur-1: 80ms   /* press */
--dur-2: 140ms  /* hover, micro */
--dur-3: 220ms  /* dialog enter / exit */

--ease-std: cubic-bezier(0.4, 0, 0.2, 1);
--ease-out: cubic-bezier(0.22, 1, 0.36, 1);

2.7   Responsive · mobile rules

Same tokens; smaller values. The system has three breakpoints — lifted from what the codebase already uses (900px, 768px, 480px) and renamed. Below the md breakpoint, the type and spacing scales each take one step down automatically via :root overrides; components don't need media queries.

--bp-sm phones — portrait, narrow tablets ≤ 480px
--bp-md phones landscape, small tablets ≤ 768px
--bp-lg tablets, narrow desktop ≤ 900px

Type · mobile shifts down one step

display-1 desktop  56px  →  mobile  40px letter-spacing -0.02em on mobile
display-2 desktop  36px  →  mobile  28px page titles
title desktop  24px  →  mobile  20px card titles
subtitle desktop  18px  →  mobile  16px sub-heading
body / body-sm / label / overline unchanged — 15 / 13 / 12 / 11 readability floor

Body sizes don't shrink — 13px is the minimum readable size in the system. Only display sizes step down so heroes and titles don't overpower the small screen.

Spacing · big steps shrink on mobile, micro stays

--space-0 → 3 2 / 4 / 8 / 12 px unchanged on mobile
--space-4 card / panel padding 16 → 12 px
--space-5 section interior 20 → 16 px
--space-6 between sections 24 → 20 px
--space-7 page gutter 32 → 20 px
--space-8 hero / between blocks 48 → 32 px

Components · what changes on touch

Hit targets

Every tappable element is ≥ 44 × 44 px on touch. Button.md (40px) becomes 44px below --bp-md; icon buttons too. Below 480px, sm buttons get bumped to md to satisfy this.

Radii

Full-bleed cards drop their radius to 0 when they hit screen edges (current Board already does this). Other radii unchanged.

Card grids

Below --bp-md, 2- and 3-column card grids collapse to single column. Below --bp-lg, 3-column becomes 2.

Dialogs

Below --bp-sm, dialog actions stack column-reverse (primary on top) and buttons go full width.

Game board

Min cell size 36px on touch (current code uses ~32px which is below the 44px hit-target rule — long-press flagging compensates).

Sticky CTAs

On mobile, primary page CTAs (Start, Continue) become sticky-bottom with safe-area padding — Lobby already does this.

Implementation

The whole responsive layer is two media queries on :root. Components reference the same tokens; nothing else changes. 

/* tokens.css \u2014 the entire responsive system */
:root {
  /* breakpoints (for use in component media queries when needed) */
  --bp-sm: 480px;
  --bp-md: 768px;
  --bp-lg: 900px;
}

@media (max-width: 768px) {
  :root {
    /* type \u2014 displays shrink, body stays */
    --fs-display-1: 40px;
    --fs-display-2: 28px;
    --fs-title:     20px;
    --fs-subtitle:  16px;

    /* spacing \u2014 large steps shrink, micro stays */
    --space-4: 12px;
    --space-5: 16px;
    --space-6: 20px;
    --space-7: 20px;
    --space-8: 32px;

    /* hit-target floor for buttons */
    --btn-h-md: 44px;
    --btn-h-sm: 40px;  /* sm bumps to "md desktop" */
  }
}

@media (max-width: 480px) {
  :root {
    --fs-display-1: 32px;
  }
}

Rule of thumb for new components: never hardcode a font-size or padding inside a @media query. If a value needs to shift on mobile, it belongs on the token. Components express intent (--fs-title) — the token decides the pixel.

Migration plan

Concrete steps. Each line is a real file in the repo. No big-bang refactor — ship the tokens first, then sweep components.

5.1   Phase 1 · Tokens (1 PR)

  • Create src/styles/tokens.css Single source of truth. Imported once from app/layout.tsx.
  • Move all :root from src/styles/globals.scss Leave only resets + body bg + Clerk override in globals.scss.
  • Add new tokens (additive — no breaking changes) Spacing 0–8, font scale, fw scale, radius 1–4, elev 1–4, focus rings, accent / danger opacity steps.
  • Add Google Fonts import for JetBrains Mono In app/layout.tsx via next/font. Wire to --font-mono.

5.3   Phase 3 · Sweep (search & replace)

  • Replace rgba(77, 163, 255, …) globally Use --accent-14 / 24 / 48. ~30 occurrences across 12 files.
  • Replace rgba(255, 92, 122, …) globally Use --danger-14 / 24 / 48. ~10 occurrences.
  • Snap all font-size: 0.XXrem to the scale Tool: ripgrep + a one-time codemod. Map the 20+ sizes to the 7 canonical ones.
  • Snap all spacings to --space-N 5/7/9/10/14/18px → nearest scale step. Keep cell-internal pixel values (board math) untouched.
  • Collapse box-shadows to elevation tokens 4 destinations: elev-1/2/3/4. Remove every inline 0 12px 30px rgba(0,0,0,…).
  • Normalize font-weights to 4 steps Anything 800/900 → 700. 600 stays. 500 introduced where 600 is too heavy (eyebrows).
  • Wrap timers / scores / mine counts in --font-mono Lock font-variant-numeric: tabular-nums. Single mono class, applied via StatTile.
  • Delete duplicate @keyframes Move to tokens.css: dialogEnter, popoverEnter, fadeIn, sheetUp.

5.4   What this buys

Coherence

Every screen pulls from the same 30-ish tokens. The "AI generated" smell — near-but-not-quite consistent spacing and weight — disappears.

Velocity

New screens compose from Card + StatTile + Badge + Button. No new SCSS module per feature.

Themability

A light mode or seasonal palette becomes a tokens-only change. Today it would be a 24-file change.
